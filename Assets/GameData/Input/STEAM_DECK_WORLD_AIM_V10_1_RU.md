# V10.1 — два режима курсора для Steam Deck / геймпада

## Установка
Содержимое HOTFIX `GameData/` положи в `Assets/GameData/` с заменой файлов.
Это продолжение V10; не удаляет и не заменяет твои JSON предметов, сцены или сохранения.

Для полноценного чтения правого стика требуется **Unity Input System** и
**Active Input Handling = Both** (как указано в README V10). В Steam Input
выбирай шаблон **Gamepad**, а не эмуляцию мыши/клавиатуры.

## Управление
- Правый стик + выбранный блок / инструмент / пустая рука: **строительный курсор**. Он двигается относительно персонажа, следует за ним, привязывается к центрам игровых клеток, ограничен окружностью в 5 блоков. Рамка голубая, размером 1 клетка.
- Правый стик + оружие: **боевой курсор**. Он сразу показывает направление стика в пределах радиуса 2.25 блока и двигается вслед за персонажем, без накопления сдвига по экрану. Если отпустить стик — остаётся в последнем направлении. Рамка-мишень оранжевая.
- **RT** — копать блок в строительном режиме или атаковать выбранным оружием.
- **LT** — разместить блок / использовать предмет.
- **X** — взаимодействие (печь, дверь и т. п.).
- **LB / RB** — листать хотбар; тип курсора переключается автоматически при выборе оружия.
- **A** — прыжок.
- Когда открывается инвентарь или меню, прицел исчезает, остаётся навигация UI по стику/крестовине.
- Если двигать физической мышкой, прицел отдаёт управление мыши. Снова коснись правого стика для возврата геймпада.
- В 3D курсор V10.1 не отображается: правый стик по-прежнему вращает камеру, центр экрана — прицел 3D.

## Настройки
Открой `Настройки → Общие`. В правой колонке появились:
- `Скорость курсора` — скорость перемещения строительной рамки (в блоках/с).
- `Радиус строительства` — максимальное расстояние курсора от игрока (ограничено дальностью взаимодействия).
- `Радиус прицела оружия` — расстояние боевого прицела от игрока (0.65–5 блоков).
- Сохранилась настройка мёртвой зоны стика.

Новые поля в `InputPreferences` имеют безопасные значения по умолчанию; старые V10 настройки сохраняются. Цвета прицелов объявлены сериализованными полями в `GamepadUIFocusDriver`.

## Технически
Новые координаты хранятся в **мировых координатах**, а в старый `GameInput.PointerPosition` возвращается проекция через текущую 2D камеру. Таким образом, существующие `BlockInteraction`, `FurniturePlacementModeController`, `MultiBlockPlayerController`, `FurnaceRuntime`, `PlayerWeaponController` и другие взаимодействия работают с одной точкой.

Боевой курсор выбирается по `WeaponMetadataRegistry` или `ItemDefinition.Type == Weapon`. Для атаки существующая система оружия всё равно требует корректную секцию `Weapon` в единственном JSON предмета.

## Проверка в Unity
1. Зайди в 2D-мир с подключённым геймпадом. Должна появиться голубая рамка на клетке справа от персонажа. Поворачивай правый стик — рамка перемещается по блокам, но не убегает за границу окружности.
2. Держи RT — блок под рамкой копается. Возьми блок в хотбар и держи LT — устанавливается блок под рамкой.
3. Выбери зарегистрированный меч — рамка должна смениться на оранжевый прицел. Направь правый стик влево и нажми RT — меч замахивается влево; направь вправо — вправо.
4. Во время движения персонажа оба прицела должны следовать за ним, при неподвижном стике не уезжать за край экрана.
5. Открой инвентарь Y — прицел скрывается, выбираются слоты; закрой — прицел возвращается.
6. В 3D прицел остаётся по центру и работает вращение камеры, без 2D рамки.

## Ограничения проверки
Код прошёл статические проверки структуры файлов, но полноценные тесты Unity Play Mode и проверка на самом Steam Deck доступны только в проекте Unity.
